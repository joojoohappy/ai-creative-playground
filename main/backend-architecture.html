架構

一個請求走過的路

重點不是有幾個方塊，而是：三條路徑都先決定 mode，才匯流到唯一一次寫檔。因此超時後才回來的殭屍 thread 不可能覆寫已經寫好的 cached 結果。

誠實層

三種結果模式

mode 和 sourceNote 都由伺服器產生，前端原樣顯示。誠實不是前端的樣式選擇 — 把這句話留在伺服器，UI 才不可能不小心說謊。

live provider 成功，回傳的 bytes 通過圖片檢查，用了使用者這次的照片。
即時生成：這張圖由你這次上傳的照片產生。
cached provider 不可用／超時／回傳非圖片，但 provenance sidecar 有效。
預備結果，不是由你這次上傳的照片生成。這張圖是 {generatedAt} 以團隊測試照片（{inputPhoto}）透過 {provider} / {model} 產生。
mock 連 sidecar 都沒有。目前所有結果都在這一格。
示意用途：這份 recipe 目前還沒有實際生成過任何結果。
規則為什麼
沒有合法 sidecar，.png 就不算 fallback系統無法假裝自己生成過東西。sidecar 損壞、缺欄位或圖片不存在 → 一律降級 mock
mode: "live" 代表真的拿到一張圖provider 輸出過的是跟上傳同一套 _is_image()。回 200 但只有文字 → 視為失敗
fallbackReason 回給前端但 UI 不顯示沒有它，T+35 之後每一種失敗看起來都一樣

Person 1 必讀

那個 route.ts 會讓整條 proxy 失效

Next.js 的 rewrites 屬於 afterFiles：任何實體 route 檔都比 proxy 優先。mosaic/app/api/generate/route.ts 裡只有 export {}，沒有 POST handler，所以請求會停在 Next 並回 405，永遠到不了 Python。

已經 git rm。需要還原的話：git checkout mosaic/app/api/generate/route.ts — 但還原之後 proxy 就不會運作。

Person 1 需要做的只有一件事 — 在 next.config.js 保留這段（已寫好）：

async rewrites() {
  return [
    { source: '/api/:path*',    destination: 'http://localhost:8000/api/:path*' },
    { source: '/static/:path*', destination: 'http://localhost:8000/static/:path*' },
  ];
}

介面

API Contract

TypeScript 型別已經填在 mosaic/types/generation.ts。Person 1 第一分鐘就能用靜態 JSON mock 起來，不會被後端卡住。

# 分辨「後端沒開」和「真的出錯」
GET  /api/health
  → 200 { ok: true }

POST /api/generate            multipart/form-data
  recipeId  string            "seed-01" | "seed-02" | "seed-03"
  image     File              jpeg | png | webp，≤8MB，以 magic bytes 判斷
  → 200 { resultId }          32 個 hex 字元
  → 400 { error: "missing_recipe_id" | "missing_image"
                 | "unsupported_type" | "too_large" }
  → 404 { error: "unknown_recipe" }

GET  /api/results/{resultId}  必須符合 ^[0-9a-f]{32}$，否則直接 404
  → 200 {
      resultId, recipeId,
      mode:           "live" | "cached" | "mock"   // 一定存在
      sourceNote:     string    // 伺服器寫的揭露文字，原樣顯示
      imageUrl:       string | null   // 只有 mode=mock 時為 null
      fallbackReason: string | null   // 除錯用，UI 不顯示
      recipeTitle, creatorName, sourcePostUrl, creatorInstagramUrl,
      createdAt       // ISO 8601 UTC
    }
  → 404 { error: "unknown_result" }

傳 recipeId，不傳 prompt。否則 API key 會變成任何人打開 devtools 就能用的免費生圖服務。

取捨

砍掉了什麼，以及為什麼

砍掉理由用什麼取代
資料庫 / ORM3 份 recipe、單一 process一份 JSON + write_text
Job queue + polling本機沒有 request timeout；同步生成可以直接卡 40 秒直接 await
圖片串流 endpoint平台原生功能FastAPI StaticFiles
GET /api/recipes靜態資料，開 endpoint 等於為了拿常數多跑一趟網路兩邊各自讀 recipes.json
Provider adapter 介面只有一個實作的介面不該存在一個 if
Retry / backoff現場 demo 重試會讓最壞等待時間加倍超時直接走 fallback
Pydantic model兩個欄位兩個 if
Docker / 部署設定Demo 跑本機./dev.sh

保留下來、不能再砍的：邊界輸入驗證、伺服器端 prompt 查找、mode / sourceNote 揭露。那是信任邊界與誠實保證。
